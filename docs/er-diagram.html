01

アカウントと主催者

登録と同時に type=USER の Organizer（個人主催者）を作る。団体を作ると type=GROUP の Organizer ができ、作成者が OWNER になる。/@slug はどちらも Organizer.slug。権限判定は canManage(organizerId, userId) に集約する。

ルール

  • Organizer.userId は type=USER のときだけ入る（CHECK 制約）
  • OrganizerMember は type=GROUP の主催者にだけ作る
  • 最後の OWNER は離脱できない（アプリのトランザクションで検証）

画面との対応

  • 主催者ページ（団体・個人）、プロフィール編集、初回設定
  • 団体作成・団体の設定（メンバー）・メンバー招待モーダル
  • フォロー中、Home の「フォロー中の新着」

補足

  • 追加 Invitation：招待リンク方式のため
  • 追加 User.isStaff：運営が記事審査と通報対応をするため
  • Auth.js Account / Session / VerificationToken（VerificationToken は関連なしのため図から省略）
02

イベントと申込

申込は Event ではなく Slot にぶら下げる（定員と価格は枠の属性）。定員判定は Slot 行を SELECT … FOR UPDATE でロックしてから数える。申込時の質問はイベントごとに主催者が設計し、回答だけが個人情報を持つ。

申込の状態遷移（§7）

  • 空きあり・無料 → CONFIRMED ／ 空きあり・有料 → PENDING_PAYMENT ／ 満員 → WAITLISTED
  • PENDING_PAYMENT → 支払い完了で CONFIRMED、期限切れで EXPIRED（Cron）
  • キャンセル・期限切れで補欠の先頭（appliedAt 順）を繰り上げ

ルール

  • 同じ枠に有効な申込は1人1件（部分一意インデックス）
  • 公開後は質問の削除・type 変更を禁止
  • 回答は Event.endAt ＋ answerRetentionDays を過ぎたら削除（Registration と Payment は残る）

補足

  • 追加 Favorite：お気に入り（仕様は未決）
  • 追加 AnswerExportLog：CSV 出力の記録（§8 で必須）
  • 追加 Event.cancelReason、RegistrationQuestion.slotIds
03

決済

MVP はモック決済だが、実決済と同じく Webhook で状態を確定する。PENDING_PAYMENT → CONFIRMED の遷移は Webhook だけが行う。失敗→再試行があるため、1つの申込に Payment は複数できる。入金先はイベントごとに指定（Phase 8 で有効化）。

ルール

  • providerRef は一意（Webhook が二重に届いても状態を二重に進めない）
  • 支払い済みの Payment があるイベントは移管できない
  • 返金は MVP では持たない（運営が決済事業者の管理画面で対応）

画面との対応

  • モック決済・確認中・参加確定・失敗・期限切れ
  • マイページの支払い待ち、参加者リストの支払い状況
04

告知・通知・通報

メールの種類（NotificationType）

  • 申込完了 / 繰り上げ / 支払い期限 / 期限切れ / 中止
  • フォロー先の新規公開 / 主催者からの告知
  • 回答削除の7日前予告（主催者宛て） / メンバー招待

配信停止（EmailCategory）

  • EVENT_UPDATES：申込・繰り上げ・期限・中止（取引メール。停止させるかは要確認）
  • FOLLOW_NEWS：フォロー先の新規公開
  • ANNOUNCEMENTS：主催者からの告知

06

制約とインデックス

Prisma で表現できないものは、マイグレーションに SQL で追記する（schema.prisma 末尾にコメントで記載）。

対象内容理由
Slot（排他）申込処理で SELECT … FOR UPDATE してから確定数を数える新歓期の同時申込で定員超過を起こさない（§7）
Registration部分一意インデックス (slotId, userId) WHERE status IN (PENDING_PAYMENT, CONFIRMED, WAITLISTED)同じ枠は1人1件。キャンセル・期限切れ後の再申込は許可
OrganizerCHECK (type = 'USER') = (userId IS NOT NULL)、slug 一意、予約語はアプリで拒否個人と団体の差を型で守る
EventCHECK answerRetentionDays IN (30, 90, 365)保持期間の選択肢（§8）
SlotCHECK capacity >= 0 AND priceYen >= 0不正値の防止
PaymentproviderRef 一意Webhook の冪等性（§9）
Cron 用Registration(status, paymentDueAt)、Event(endAt)期限切れ→繰り上げ、回答の自動削除と7日前予告
一覧・検索用Event(status, startAt)、Event(targetUniversityId, startAt)、pg_trgm の GIN（title）Events 一覧・カレンダー・キーワード検索
通知NotificationLog(userId, createdAt)、(type, status)再送・配信状況の確認
