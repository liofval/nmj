ワイヤーフレームと画面別機能

デザイナーへの発注仕様として、各画面のレイアウトと大まかな機能を定義する。要件定義書 §10 の情報設計を土台に、画面ごとの構成要素・表示データ・主な遷移を並列する。ワイヤーフレームは意図の伝達を優先し、精緻な寸法や配色は含めない。

§0共通レイアウト

参加者向けの全画面に共通する骨格。ヘッダは Home / Media / Events の3タブと、右上のログイン導線。主催者向けの管理画面は"完全別リンク"として、参加者側とは独立したヘッダを持つ。

未ログイン

└────────────────────────────────────────────────────────┘

ログイン後（右上のみ変化）
┌────────────────────────────────────────────────────────┐

フッタ（全画面共通）

│  © 2026 nmj                                              │
└────────────────────────────────────────────────────────┘

ヘッダ（主催者側・完全別リンク）

主催者ダッシュボード配下のみに出るヘッダ。参加者側ヘッダは出ない。
┌────────────────────────────────────────────────────────┐
│  [logo studio]  Overview  Events  Members     [参加者側へ →] │
└────────────────────────────────────────────────────────┘

デバイス方針

  • モバイルファースト。ワイヤーフレームは PC 幅で書いているが、実装はスマホ幅（375〜428px）を最優先で設計する
  • スマホ幅ではヘッダのタブが横スクロール、フッタは折りたたみ、カードは1列縦積みが原則
  • タッチターゲットは最小 44×44px

共通コンポーネント（デザイナーに揃えてほしいもの）

  • イベントカード: cover 画像 / タイトル / 主催者 slug / 日付 / 会場種別（対面・オンライン） / 残席バッジ
  • 主催者カード: アイコン / ユーザーネーム / あだ名 / 大学（任意） / フォロワー数 / [フォロー] ボタン
  • タグ: 大学名・カテゴリ・会場種別
  • 空状態: リストが空のとき（新歓期外・フォロー0件・お気に入り0件など）に出すプレースホルダ
  • トースト: 申込完了・キャンセル完了・エラーの一時表示

表示データ

  • cover 画像、タイトル、主催者 (@slug + 表示名)、対象大学、日時、会場種別と場所、説明本文（Markdown）

§5申込フロー /events/[id]/apply

3ステップで完結する。枠選択 → 質問回答 → 確認 → 無料は完了、有料は決済へ。ステップ間で戻れる。個人情報の取り扱い（回答を見る人・保持期間）は確認ステップで必ず明示する。

できること

  • 複数枠に同時に申込
  • ステップ間で戻る（回答は保持）
  • 個人情報取扱いへの同意（未同意ではCTA無効化）
  • 有料枠は決済画面へ、無料枠は即確定

特記

  • 満員枠を選ぶと CTA は「補欠登録」に変わる（キャンセル発生時に自動繰上げ）
  • すでに申込済みの枠はグレー表示＋「申込済み」ラベル
