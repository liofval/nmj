使い方・画面一覧・v0.2 からの変更点・要判断事項

使い方

  • ワイヤー内のボタン・カード・タブをクリックすると、その先の画面へ遷移します。モーダルは画面の上に開きます（× か背景クリックで閉じる）。
  • クリックできる場所はマウスを乗せると青い点線が出ます。ツールバーの「リンク箇所を表示」で全部を常時ハイライトできます。
  • 「◀ 戻る」またはブラウザの戻る、キーボードの ← → でも移動できます。URL の #画面ID で画面を直接開けます。
  • PC は画面幅に合わせて伸縮、SP は 375px。「端末枠でスクロール」をオフにするとページ全体が縦に伸びます（印刷・PDF はこの状態で全画面を出力）。
  • 右の「メモ」は画面ごとにこのブラウザへ自動保存されます。「メモ入りHTMLを書き出す」で共有用ファイルを作れます。

共通方針

  • グローバルタブは Home / Media / Events の3つ。ログインが必要な入口はヘッダ右上に集める。
  • 主催者側（濃いヘッダ）は完全別リンク。ロゴは主催者ダッシュボードへ戻り、参加者側へは右上の明示リンクで戻る。
  • 画面に出る人名はあだ名と @ユーザーネームだけ。本名・連絡先は申込時の回答として、主催者の参加者リストにだけ出る。
  • モバイルファースト。タッチ領域は最小 44×44px、コントラスト比 4.5:1 以上、全フォームにラベル。
  • 1タップで戻せる操作（フォロー・お気に入り）は確認を出さない。破壊的操作は警告色＋キャンセルを左。

要判断（ワイヤー上で仮置きしたもの）

#論点仮置き
1要件 §10 のパスは /events/new・/@[slug]/settings だが、主催者側は「独立した URL 空間」とも書かれている要件のパスのまま、主催者側ヘッダで描いた。/manage/… に寄せるか要決定
2検索の「主催者」タブ要件は「キーワード・大学・日付範囲」のみ。団体を探す新入生向けに追加
3/search と /events の絞り込みの重複🔍 は横断検索、Events タブは一覧の絞り込み、と入口を分けた
4カレンダー追加（Google / .ics）、状態バッジの体系v0.1 から継承。要件 §4 のスコープ表に行がない
5公開後の保持期間の変更可否、OWNER 限定の操作、告知メールの返信先画面説明に「要確認」と記載
6お気に入りの仕様、Media の入稿とカテゴリ、ユーザーネームの初期値と変更制限要件 §14 の未決のまま最小構成

1. Home/公開

季節 hero と注目コンテンツで Events / Media / 主催者ページへ振り分ける入口。ログイン中は「フォロー中の新着」を差し込む。

できること

  • hero の CTA から Events 一覧へ
  • カードからイベント詳細・記事詳細へ
  • 大学タグで Events を大学絞り込み付きで開く（/events?university=keio）
  • （ログイン中）フォロー中主催者の新着

表示データ

  • hero：季節で差し替え（運営が設定）
  • フォロー中の新着：フォロー先の公開イベント、開催日が近い順
  • 注目のイベント：運営のピックアップ

2. Events 一覧/events公開

絞り込み条件は URL パラメータに載せ、カレンダーとの切り替えでも引き継ぐ。SP は絞り込みをチップ＋ボトムシート、PC は左カラムに常設。

できること

  • キーワード・大学・開催日・会場種別で絞り込む（SP は「⚙ 絞り込み」でシート）
  • 並び順の切替（開催日が近い順 / 新着順）
  • 同じ条件のままカレンダーへ

表示データ

  • カード：cover・タイトル・主催者・対象大学・会場・日時・残席・価格レンジ
  • 公開中のみ。終了済みは既定で出さない

3. Events カレンダー/events/calendar公開

同じデータ集合を月次で見る。開催日にドット、日付を選ぶとその日のイベントを下（PC は右）に出す。

できること

  • 月移動・当月へ戻る
  • 日付を選んでその日のイベントを表示
  • 一覧と同じ条件のまま切替

表示データ

  • 日ごとの件数（ドット。4件以上は「+n」）
  • 選択日のイベントカード

4. イベント詳細/events/[id]公開

検討から申込ボタンまでを1画面で。枠ごとの残席と価格、主催者、申込時に聞かれること（個人情報・保持期間・利用目的）を申込前に見せる。SP は画面下に申込 CTA を固定、PC は右カラムに参加枠を固定。

できること

  • 枠ごとに申込／満員枠は補欠登録
  • Google カレンダー追加・.ics
  • お気に入り・フォロー・シェア・通報（未ログインはログイン促進モーダル）
  • オンラインの URL は参加確定者にだけ表示

未ログインで申込

  • ログイン促進 → ログイン後に申込フローへ戻る（/login?next=…）
  • このプロトタイプでは直接申込へ進む

状態

  • 受付前・受付中・満員・締切・申込済み・支払い待ち・補欠中・中止・終了 → 4b 状態違いを参照

4b. イベント詳細の状態違い/events/[id]公開

スクリーンショットを見ただけでどの状態か分かることを要件にする。上部バナーと固定 CTA が変わる（SP）。

状態ごとの CTA

  • 受付前：押せない＋受付開始日時 ／ 受付中：申し込む ／ 満員：補欠登録
  • 締切・中止・終了：固定 CTA 非表示
  • 申込済み・補欠中：マイページで見る ／ 支払い待ち：支払いへ進む

5. 検索/search公開

ヘッダの🔍から入る横断検索（キーワード・大学・日付範囲）。結果は「イベント」「主催者」の2タブ（主催者タブは要判断）。

できること

  • キーワード（タイトル・説明・主催者名）で探す
  • 大学・日付範囲で絞り込む
  • 主催者を探してフォロー

次の画面

  • キーワードを押すと 5b 検索結果へ

5b. 検索結果/search?q=軽音公開

イベントタブ。主催者タブは 5 検索のSP右側を参照。

6. Media 一覧/media公開

読み物・特集・主催者インタビュー。SEO とオーガニック集客の入口。入稿導線・カテゴリは未決（要件 §14）なのでカテゴリは仮置き。

7. Media 記事詳細/media/[slug]公開

本文の末尾に関連イベント・主催者カードを置き、イベントへ回遊させる。

8. 主催者ページ（団体）/@[slug]公開

団体・個人で共通の画面。団体は cover・紹介文・運営メンバーを加える。大学はプロフィールに持たない。

できること

  • フォロー／解除（未ログインはログイン促進）
  • SNS リンク（本人確認しないので認証マークは出さない）
  • 今後・過去のイベント
  • 「…」から通報
  • 自分が管理者なら「管理画面へ」を表示

表示データ

  • 共通：アイコン・あだ名・@slug・SNS・フォロワー数・イベント数
  • 団体のみ：cover・紹介文・運営メンバー

8b. 主催者ページ（個人）/@[slug]公開

個人は cover・紹介文を出さず、所属している団体を加える（要件 §5・§10）。

9. ログイン/login参加者

Google ログインのみ。初回は個人の主催者アカウントが自動生成され、初回設定へ。?next= で元の画面に戻す。

9b. 初回のプロフィール設定/login（初回のみ）参加者

4項目（アイコン・ユーザーネーム・あだ名・SNS）。本名は登録しない。

10. 申込 ① 枠選択/events/[id]/apply参加者

複数枠に同時申込できる（本編＋懇親会）。満員枠は補欠登録になる。単一枠のイベントはこのステップを飛ばす。

10b. 申込 ② 質問への回答/events/[id]/apply参加者

主催者が設計した質問。枠限定の質問はその枠を選んだときだけ出す。プロフィールに保存しない（ブラウザの自動入力に任せる）。

10c. 申込 ③ 確認/events/[id]/apply参加者

「回答を見る人」「保持期間」「利用目的」「有料枠は返金なし」を申込ボタンの手前に必ず出し、同意を取る（要件 §7・§8）。有料枠を含むので決済へ。

10d. 申込完了（無料枠のみ）/events/[id]/apply/done参加者

無料枠は即確定。補欠は番号を表示し、繰り上げ時にメール（有料枠は繰り上げ後に支払い期限が付く）。

11. モック決済/mock/checkout/[ref]参加者

MVP はアプリ内の疑似決済画面。「支払う」「失敗させる」の2ボタンで自前の Webhook を叩き、状態は Webhook でだけ確定する（要件 §9）。Phase 8 で Stripe Checkout（ホスト画面）へ差し替え。

11b. 支払いの確認中戻り先 URL参加者

戻り先の画面では確定させない。Webhook で PENDING_PAYMENT → CONFIRMED になるまで待つ。

11c. 参加確定戻り先 URL参加者

確認メールを送信。当日の受付は主催者の参加者リストでタップして行う（受付コードは持たない）。

11d. 支払い失敗戻り先 URL参加者

申込は支払い待ちのまま残る。期限内なら同じ申込で再試行できる。

11e. 支払い期限切れ/events/[id] ほか参加者

Cron で EXPIRED 化 → 枠を解放して補欠を繰り上げ。期限切れの申込からアクセスしたときの表示。

12. マイページ/me参加者

ヘッダ右上のアイコンから入る。プロフィール、参加予定・支払い待ち・補欠中・履歴、お気に入り、フォロー中、自分が管理する主催者への切り替え（完全別リンク）。

できること

  • プロフィール編集（4項目のみ）
  • 申込の確認・キャンセル・回答の訂正
  • 支払い待ちの再開、補欠の取り下げ
  • 主催者側へ切り替え（参加者側タブ帯が消える）
  • 新しい団体を作る

キャンセルのルール

  • 開始後はキャンセル不可（ボタンを出さない）
  • 無料枠は開始前ならいつでも可
  • 有料枠の支払い済みは返金なし

12b. マイページ：支払い待ち・補欠中/me?tab=pending参加者

支払い期限と「支払う」を目立たせる。補欠は順番と取り下げ。

12c. プロフィール編集/me/edit参加者

個人・団体で共通のフォーム。団体の設定ではここに紹介文と cover が加わる。

13. フォロー中の主催者/me/following参加者

主催者ごとの次のイベントを並べる。フォロー解除は確認なし（トーストに「元に戻す」）。

13b. お気に入りイベント/me/favorites参加者

イベント単位の保存。並び順・開催前リマインド・上限・共有可否は未決（要件 §14、Phase 2）。

14. 主催者ダッシュボード/manage/@[slug]主催

完全別リンク。参加者側タブ帯は出さず主催者側ヘッダを持つ。イベントの状況をひと目で見て、参加者リスト・告知・編集へ。個人主催も同じ画面（メンバー項目がないだけ）。

できること

  • イベント作成・下書きの編集と公開
  • 参加者リスト・告知・編集・複製・移管・中止
  • 回答削除の予告を確認し、控えを取る

表示データ

  • フォロワー数・公開中件数・今月の申込数
  • 枠ごとの確定数/定員、補欠数、支払い待ち数
  • 最近の申込（あだ名のみ）

15. 団体作成/groups/new主催

作成と同時に団体の主催者アカウントが生まれ、作成者が OWNER になる。入力項目はプロフィール＋紹介文・cover。

16. 団体の設定/@[slug]/settings主催

プロフィール・メンバー・入金先（後日）の3タブ。ロールは OWNER / ADMIN。最後の OWNER は離脱できない（UC-3）。

権限

  • OWNER・ADMIN ともイベントの作成・編集・参加者閲覧ができる（canManage）
  • OWNER の追加・降格・団体削除は OWNER のみ（要確認）

入金先

  • Phase 8 で有効化。MVP はタブだけ置いて「準備中」

17. イベント作成・編集/events/new主催

冒頭で主催者と対象の大学を選ぶ。6セクションに分け、PC は左に目次、SP は下に保存バーを固定。公開後は質問の削除と形式変更を禁止（要件 §8）。

公開時のチェック

  • 必須：主催者・大学・タイトル・日時・会場・枠1つ以上
  • 個人情報の質問があれば利用目的が必須
  • 公開でフォロワーにメール通知（確認モーダルで件数を表示）

公開後の編集制限

  • 質問：削除・形式変更は不可。追加・並べ替え・文言修正は可
  • 枠：定員を確定数未満にできない
  • 保持期間は短くする方向のみ（要確認）

18. 参加者リスト・受付/manage/events/[id]/attendees主催

当日は運営が片手で操作する前提。SP は1人1カードでタップして受付、PC は表で回答・支払い状況を一覧して CSV 出力。回答は主催者にしか見えない。

できること

  • 枠で絞り込み・検索・未受付のみ
  • タップで受付済 ↔ 未受付（誤タップを戻せる）
  • 回答の確認、CSV 出力（出力は記録に残る）

表示・権限

  • 保持期間後、回答欄は「削除済み」
  • サーバー側で毎回 canManage を検証（URL を推測しても見えない）

19. 告知配信/manage/events/[id]/announce主催

参加者への一斉メール。宛先は「確定者」か「補欠を含む全員」。送信履歴を残す。

20. イベント移管/manage/events/[id]/transfer主催

個人で立てたイベントを自分が管理する団体へ移す（UC-5）。参加者・申込・支払い状況・URL はそのまま。候補は自分が管理する団体だけ。団体→個人は UI で提供しない。

20b. 移管できない場合/manage/events/[id]/transfer主催

支払い済みの申込が1件でもあると移管不可。理由を示して操作を無効化する。

21. モーダル一覧

SP は下から出るシート、PC は中央ダイアログ。ESC・背景・× で閉じる、フォーカストラップ、背景スクロールロック。各画面のボタンから実際に開けます。

呼び出し元

  • ログイン促進：未ログインでお気に入り・フォロー・申込
  • 申込キャンセル：マイページ
  • シェア・通報：イベント詳細・主催者ページ・記事
  • 絞り込み：Events（SP）

主催者側

  • 公開確認：イベント作成・下書き
  • 中止確認：ダッシュボード
  • メンバー招待：団体の設定
  • CSV 出力確認：参加者リスト・お知らせ
