使い方

  • ワイヤー内のボタン・カード・タブをクリックすると、その先の画面へ遷移します。モーダルは画面の上に開きます（× か背景クリックで閉じる）。
  • クリックできる場所はマウスを乗せると青い点線が出ます。ツールバーの「リンク箇所を表示」で全部を常時ハイライトできます。
  • 「◀ 戻る」またはブラウザの戻る、キーボードの ← → でも移動できます。URL の #画面ID で画面を直接開けます。
  • PC は画面幅に合わせて伸縮、SP は 375px。「端末枠でスクロール」をオフにするとページ全体が縦に伸びます（印刷・PDF はこの状態で全画面を出力）。
  • 右の「メモ」は画面ごとにこのブラウザへ自動保存されます。「メモ入りHTMLを書き出す」で共有用ファイルを作れます。

共通方針

  • グローバルタブは Home / Media / Events の3つ。ログインが必要な入口はヘッダ右上に集める。
  • 主催者側（濃いヘッダ）は完全別リンク。ロゴは主催者ダッシュボードへ戻り、参加者側へは右上の明示リンクで戻る。
  • 画面に出る人名はあだ名と @ユーザーネームだけ。本名・連絡先は申込時の回答として、主催者の参加者リストにだけ出る。
  • モバイルファースト。タッチ領域は最小 44×44px、コントラスト比 4.5:1 以上、全フォームにラベル。
  • 1タップで戻せる操作（フォロー・保存）は確認を出さない。破壊的操作は警告色＋キャンセルを左。

要判断（ワイヤー上で仮置きしたもの）

#論点仮置き
1要件 §10 のパスは /events/new・/@[slug]/settings だが、主催者側は「独立した URL 空間」とも書かれている要件のパスのまま、主催者側ヘッダで描いた。/manage/… に寄せるか要決定
2検索の「主催者」タブ団体を探す人向けに追加（フォローできるのは団体だけ）
3/search と /events の絞り込みの重複🔍 は横断検索、Events タブは一覧の絞り込み、と入口を分けた
4カレンダー追加（Google / .ics）、状態バッジの体系v0.1 から継承。要件 §4 のスコープ表に行がない
5公開後の保持期間の変更可否、告知メールの返信先画面説明に「要確認」と記載
6Media の入稿とカテゴリ、ユーザーネームの初期値と変更制限要件 §14 の未決のまま最小構成
7団体を削除したとき・代表が抜けたときの扱い（イベント・フォロワー・申込をどうするか、引き継ぎ）削除は運営（NMJ）に依頼する形で仮置き。owner が1人でも残っていれば団体は続く
8同じ団体のページが複数できるのを防ぐ方法（申請はなし）作成時に似た名前の団体を表示して「既存の団体に参加を依頼」へ誘導。重複は運営が統合・削除
9個人情報をどこまで扱うか（共通の質問の中身・保持期間・CSV 出力）共通の質問は「氏名・フリガナ・所属（学校名と学年 / 社会人）」で仮置き
10通報の項目理由（必須）＋詳細で仮置き。項目は検討中
11QR チケットの Wallet（Apple / Google）追加ボタンだけ置いて「検討中」
12個人主催のイベントを残すか（フォローは団体のみになったため）個人主催は残し、フォローボタンだけ出さない
13イベントの「対象の大学」を残すか（大学の絞り込みはなくした）画面からは外した。DB には残している

1. Home/公開

季節 hero と注目コンテンツで Events / Media / 主催者ページへ振り分ける入口。ログイン中は「フォロー中の新着」を差し込む。

できること

  • hero の CTA から Events 一覧へ
  • カードからイベント詳細・記事詳細へ
  • ジャンル・地域のタグで Events を絞り込み付きで開く（/events?genre=music）
  • （ログイン中）フォロー中の団体の新着

表示データ

  • hero：季節で差し替え（運営が設定）
  • フォロー中の新着：フォロー先の公開イベント、開催日が近い順
  • 注目のイベント：運営のピックアップ

2. Events 一覧/events公開

絞り込み条件は URL パラメータに載せ、カレンダーとの切り替えでも引き継ぐ。SP は絞り込みをチップ＋ボトムシート、PC は左カラムに常設。

できること

  • キーワード・ジャンル・地域・参加枠（学生 / 大人 / 懇親会）・開催日で絞り込む（SP は「⚙ 絞り込み」でシート）。大学・参加費では絞り込まない
  • 並び順の切替（開催日が近い順 / 新着順）
  • 同じ条件のままカレンダーへ

表示データ

  • カード：cover・タイトル・主催者・ジャンル・地域・日時・残席・価格レンジ
  • 公開中のみ。終了済みは既定で出さない

3. Events カレンダー/events/calendar公開

同じデータ集合を月次で見る。開催日にドット、日付を選ぶとその日のイベントを下（PC は右）に出す。

できること

  • 月移動・当月へ戻る
  • 日付を選んでその日のイベントを表示
  • 一覧と同じ条件のまま切替

表示データ

  • 日ごとの件数（ドット。4件以上は「+n」）
  • 選択日のイベントカード

4. イベント詳細/events/[id]公開

検討から申込ボタンまでを1画面で。枠ごとの残席と価格、主催者、申込時に聞かれること（個人情報・保持期間・利用目的）を申込前に見せる。SP は画面下に申込 CTA を固定、PC は右カラムに参加枠を固定。

できること

  • 枠ごとに申込。満員の枠とイベント全体の上限に達したときは申し込めない（補欠はなし）
  • Google カレンダー追加・.ics
  • 保存・団体のフォロー・リンクのコピー・通報（未ログインはログイン促進モーダル）
  • オンラインの URL は参加予定の人にだけ表示

未ログインで申込

  • ログイン促進 → ログイン後に申込フローへ戻る（/login?next=…）
  • このプロトタイプでは直接申込へ進む

状態

  • 受付前・受付中・満員・締切・参加予定・中止・終了 → 4b 状態違いを参照

4b. イベント詳細の状態違い/events/[id]公開

スクリーンショットを見ただけでどの状態か分かることを要件にする。上部バナーと固定 CTA が変わる（SP）。

状態ごとの CTA

  • 受付前：押せない＋受付開始日時 ／ 受付中：申し込む ／ 満員：押せない（補欠なし）
  • 締切・中止・終了：固定 CTA 非表示
  • 参加予定：QR チケット

5. 検索/search公開

ヘッダの🔍から入る横断検索（キーワード・ジャンル・地域・日付範囲）。結果は「イベント」「団体」の2タブ。

できること

  • キーワード（タイトル・説明・主催者名）で探す
  • ジャンル・地域・日付範囲で絞り込む
  • 団体を探してフォロー

次の画面

  • キーワードを押すと 5b 検索結果へ

5b. 検索結果/search?q=軽音公開

イベントタブ。団体タブは 5 検索のSP右側を参照。

6. Media 一覧/media公開

読み物・特集・主催者インタビュー。SEO とオーガニック集客の入口。入稿導線・カテゴリは未決（要件 §14）なのでカテゴリは仮置き。

7. Media 記事詳細/media/[slug]公開

本文の末尾に関連イベント・主催者カードを置き、イベントへ回遊させる。

8. 主催者ページ（団体）/@[slug]公開

団体・個人で共通の画面。団体は cover・紹介文・運営メンバーを加える。大学はプロフィールに持たない。

できること

  • フォロー／解除（未ログインはログイン促進）。フォローできるのは団体だけ
  • SNS リンク（本人確認しないので認証マークは出さない）
  • 今後・過去のイベント
  • 「…」から通報
  • 自分が管理者なら「管理画面へ」を表示

表示データ

  • 共通：アイコン・あだ名・@slug・SNS・フォロワー数・イベント数
  • 団体のみ：cover・紹介文・運営メンバー（owner は複数人）

8b. 主催者ページ（個人）/@[slug]公開

個人は cover・紹介文を出さず、所属している団体を加える（要件 §5・§10）。個人はフォローできない（10/8 決定）のでフォローボタンを出さない。

9. ログイン/login参加者

Google ログインのみ。初回は個人の主催者アカウントが自動生成され、初回設定へ。?next= で元の画面に戻す。

9b. 初回のプロフィール設定/login（初回のみ）参加者

4項目（アイコン・ユーザーネーム・あだ名・SNS）。本名は登録しない。

10. 申込 ① 枠選択/events/[id]/apply参加者

複数枠に同時申込できる（学生枠＋懇親会など）。満員の枠は選べない（補欠なし）。イベント全体の上限に達したら申込を止める。単一枠のイベントはこのステップを飛ばす。

10b. 申込 ② 質問への回答/events/[id]/apply参加者

全イベント共通の質問（削除不可）＋主催者が追加した質問。枠限定の質問はその枠を選んだときだけ出す。プロフィールに保存しない（ブラウザの自動入力に任せる）。

10c. 申込 ③ 確認/events/[id]/apply参加者

「回答を見る人」「保持期間」「利用目的」「有料枠は返金なし」を申込ボタンの手前に必ず出し、同意を取る（要件 §7・§8）。有料枠を含むので決済へ。決済が完了するまで申込は作られない（支払い待ちの状態は持たない）。

10d. 申込完了（無料枠のみ）/events/[id]/apply/done参加者

無料枠は申込と同時に参加予定。QR チケットを発行し、マイページとメールで届ける。

11. モック決済/mock/checkout/[ref]参加者

MVP はアプリ内の疑似決済画面。「支払う」「失敗させる」の2ボタンで自前の Webhook を叩き、状態は Webhook でだけ確定する（要件 §9）。Phase 8 で Stripe Checkout（ホスト画面）へ差し替え。

11b. 支払いの確認中戻り先 URL参加者

戻り先の画面では確定させない。決済完了の Webhook を受けて申込（参加予定）が作られるまで待つ。

11c. 参加予定（決済完了）戻り先 URL参加者

申込（参加予定）と QR チケットを作り、確認メールに QR を載せる。当日は受付で QR を読み取る。

11d. 支払い失敗戻り先 URL参加者

決済が完了していないので申込は作られていない。確保していた席は解放される。

12. マイページ/me参加者

ヘッダ右上のアイコンから入る。プロフィール、お知らせ、参加予定（QR チケット）・履歴、保存したイベント、フォロー中、自分が管理する主催者への切り替え（完全別リンク）。

できること

  • プロフィール編集（4項目のみ）
  • お知らせの確認（同じ内容がメールにも届く）
  • QR チケットの表示、申込の確認・キャンセル・回答の訂正
  • 主催者側へ切り替え（参加者側タブ帯が消える）
  • 新しい団体を作る

キャンセルのルール

  • 開始後はキャンセル不可（ボタンを出さない）
  • 無料枠は開始前ならいつでも可
  • 有料枠の支払い済みは返金なし

12b. QR チケット/me/tickets/[id]参加者

申込（無料は申込時、有料は決済完了時）に発行。マイページから開くほか、確認メールにも同じ QR を載せる。受付で主催者が読み取ると受付済になる。

12c. プロフィール編集/me/edit参加者

個人・団体で共通のフォーム。団体の設定ではここに紹介文と cover が加わる。

13. フォロー中の団体/me/following参加者

フォローしている団体ごとの次のイベントを並べる（個人はフォローできない）。フォロー解除は確認なし（トーストに「元に戻す」）。

13b. 保存したイベント/me/favorites参加者

「お気に入り」から「保存」に名前を変更（10/8）。イベント単位で保存し、主催者は保存した人にもお知らせメールを送れる。並び順・上限は未決。

14. 主催者ダッシュボード/manage/@[slug]主催

完全別リンク。参加者側タブ帯は出さず主催者側ヘッダを持つ。イベントの状況をひと目で見て、参加者リスト・告知・編集へ。個人主催も同じ画面（メンバー項目がないだけ）。

できること

  • イベント作成・下書きの編集と公開
  • 参加者リスト・QR で受付・告知・編集・複製・移管・中止
  • 回答削除の予告を確認し、控えを取る

表示データ

  • フォロワー数・公開中件数・今月の申込数
  • 枠ごとの参加予定数/定員、イベント全体の上限、保存した人の数
  • 最近の申込（あだ名のみ）

15. 団体作成/groups/new主催

申請なしで作れる。作成と同時に団体の主催者アカウントが生まれ、作成者が owner になる。同じ団体のページが増えないよう、似た名前の団体があれば先に案内する。

16. 団体の設定/@[slug]/settings主催

プロフィール・メンバー・入金先（後日）の3タブ。団体の権限は owner だけ（複数可）。最後の owner は離脱できない（UC-3）。NMJ 運営（admin）は全団体を管理できる。

権限

  • admin：NMJ 運営。全団体・通報を管理
  • owner：団体の管理者（複数可）。イベントの作成・編集・参加者閲覧・メンバー招待
  • user：一般の参加者
  • 団体の削除・引き継ぎの扱いは未決

入金先

  • Phase 8 で有効化。MVP はタブだけ置いて「準備中」

17. イベント作成・編集/events/new主催

冒頭で主催者・ジャンル・地域を選ぶ。6セクションに分け、PC は左に目次、SP は下に保存バーを固定。公開後は質問の削除と形式変更を禁止（要件 §8）。

公開時のチェック

  • 必須：主催者・ジャンル・地域・タイトル・日時・会場・枠1つ以上（枠ごとに種類と定員）
  • 個人情報の質問があれば利用目的が必須
  • 公開でフォロワーにメール通知（確認モーダルで件数を表示）

公開後の編集制限

  • 質問：削除・形式変更は不可。追加・並べ替え・文言修正は可
  • 枠・全体の上限：参加予定の人数より少なくできない
  • 保持期間は短くする方向のみ（要確認）

18. 参加者リスト・受付/manage/events/[id]/attendees主催

当日は運営が片手で操作する前提。基本は QR を読み取って受付し、ここでは受付の状態（未受付 / 受付済 / 欠席）をいつでも変更・取り消しできる。PC は表で回答・支払い状況を一覧して CSV 出力。回答は主催者にしか見えない。

できること

  • 枠・受付の状態で絞り込み・検索
  • 受付の状態を 未受付 / 受付済 / 欠席 で切り替え（いつでも戻せる。誰がいつ変えたかを記録）
  • QR で受付した人は自動で受付済になる
  • 回答の確認、CSV 出力（出力は記録に残る）

表示・権限

  • 保持期間後、回答欄は「削除済み」
  • サーバー側で毎回 canManage を検証（URL を推測しても見えない）

18b. QR で受付/manage/events/[id]/checkin主催

スマホのカメラで参加者の QR チケットを読み取ると、その場で受付済になる。読めないときは参加者リストで状態を変える。

できること

  • QR を読むと受付済にして参加者情報を表示
  • 直前の受付を取り消す
  • 二重読み取り・別イベント・キャンセル済みのチケットは警告

表示・権限

  • このイベントの owner と NMJ 運営だけが使える
  • 受付の記録に「誰が・いつ・QR かリストか」を残す

19. 告知配信/manage/events/[id]/announce主催

一斉のお知らせ。サイト内のお知らせとメールの両方に届く。宛先は「参加予定の人」「保存した人（未申込）」から選ぶ。送信履歴を残す。

20. イベント移管/manage/events/[id]/transfer主催

個人で立てたイベントを自分が管理する団体へ移す（UC-5）。参加者・申込・支払い状況・URL はそのまま。候補は自分が管理する団体だけ。団体→個人は UI で提供しない。

20b. 移管できない場合/manage/events/[id]/transfer主催

支払い済みの申込が1件でもあると移管不可。理由を示して操作を無効化する。

22. 通報の確認（NMJ 運営）/admin/reports運営

admin（NMJ 運営）だけが入れる。通報が届くと運営にメールが届き、ここで対応状況を管理する。団体の統合・削除もここから（扱いは検討中）。

21. モーダル一覧

SP は下から出るシート、PC は中央ダイアログ。ESC・背景・× で閉じる、フォーカストラップ、背景スクロールロック。各画面のボタンから実際に開けます。

呼び出し元

  • ログイン促進：未ログインで保存・フォロー・申込

主催者側

  • 中止確認：ダッシュボード

  • CSV 出力確認：参加者リスト・お知らせ
